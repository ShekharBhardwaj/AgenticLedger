# 0.10 "Everywhere, live" design

Status: APPROVED by user zero on 2026-08-19 (decisions in section 8).
Nothing below is built yet; Phase A.0 starts from here.
Issues: #99 (this doc), #94 adapters, #95 Bedrock, #96 Live Loop,

The 0.9.2 cycle produced fifteen findings that reduce to four bug
classes. This document is the set of contracts that retires the
classes, plus the provider architecture and the enterprise-trust

been different last cycle if the contract had existed.

## 1. The canonicalization contract

**Problem.** Wire content is salted per request by clients (billing
nonces, migrating cache markers, session-unique paths). Today the
stability filters live where each consumer happened to need them:
`loops._stable_system_text` for run signatures, `loops._stable_content`
for thread chains, nothing for `detect.py`. Every new kind of salt is a
fresh hunt (#80, #89, #90 were three hunts for one animal).

**Contract.** One module, `proxy/canonical.py`, owns the whole journey
from wire to stable meaning:

- `CanonicalRequest` / `CanonicalResponse` stay what they are today
  (`normalize.py` moves in, callers keep their imports via shims).
- New: every `CanonicalRequest` carries a lazily computed `stable` view:
  - `stable.system_text`: system prompt minus volatile blocks and
    masked UUIDs (today's `_stable_system_text`, promoted).
  - `stable.system_digest`: hash of the above.
  - `stable.message_chain`: per-message digests over stable content
    (today's `_message_chain` + `_stable_content`, promoted).
- The volatile-content rules (block prefixes to drop, patterns to mask)
  live in ONE table in this module, with a comment per entry naming the
  real-world traffic that demanded it and the fixture that pins it.
- **The rule: no identity signal may hash wire bytes.** Loop
  signatures, thread chains, framework detection, and session inference
  consume the stable view only. A grep-able invariant: outside
  `canonical.py`, nothing calls `hashlib` on request content.

**Last cycle, restated.** #89 would have been one entry in one table
plus one fixture, healing loops, threads, pairing, and flags at once,
instead of three separate incidents weeks apart.

## 2. The attribution pipeline

**Problem.** "Which run and session does this call belong to" is
answered in several places: path parsing in `app.py`, header merge,
`detect.py`, and `LoopTracker` grouping at capture, with a read-only
twin (`resolve_run`) bolted on for the kill gate after #74, and a
second bolt (`observe_blocked`) after #77. Two brains, synced by hand.

**Contract.** One resolver, two verbs:

    Attribution = resolve(headers, path, canonical_request)
      -> {session_id, run_id, iteration, framework, agent_name,
          source: explicit | inferred | none}

    commit(action_id, attribution)   # capture only: updates state

- The kill gate calls `resolve` and never anything else. Capture calls
  `resolve` then `commit`. Refusals call `commit` too, with a
  `refused=True` mark, which is what keeps walls airtight (#77) without
  a special observer method.
- Explicit beats inferred, always; `source` is stored so the dashboard
  can honestly show "named by you" vs "grouped by the ledger".
- `LoopTracker` becomes the resolver's private engine rather than a
  peer that other code talks to directly.

**Last cycle, restated.** #74 and #77 could not have existed: there is
no second copy of grouping logic to fall out of sync, and refusals are
first-class events in the only pipeline there is.

## 3. The provider adapter contract

**Problem.** `detect_provider` keys off the URL path; OpenAI and
Anthropic logic is interleaved through `normalize.py`, `stream.py`, and
`app.py`. Azure is mispriced; Bedrock, Gemini, and Vertex capture
nothing useful; every new provider means edits in four files.

**Contract.** `proxy/providers/` with one class per provider:

    class Provider(Protocol):
        name: str
        def matches(path, headers, body) -> bool
        def normalize_request(body, path) -> CanonicalRequest
        def normalize_response(body, latency_ms) -> CanonicalResponse
        def reconstruct_stream(body_bytes, latency_ms) -> CanonicalResponse
        def extract_tool_results(messages) -> list
        def upstream_default() -> str | None
        # The question every adapter MUST answer in writing:
        attribution_story: str   # how run/session tags survive THIS wire

- Registry walk replaces `detect_provider`; first `matches` wins;
  explicit upstream config still overrides routing exactly as today.
- Existing OpenAI/Anthropic/Responses logic moves into
  `providers/openai.py` and `providers/anthropic.py` with the current
  functions kept as shims, so nothing outside the package changes in
  Phase A.
- Azure OpenAI ships inside Phase A as the proof: same wire shape as
  OpenAI, different host fingerprint and model-id prefixes; its adapter
  is mostly configuration, and its prices become correct.

**The attribution story requirement, illustrated by Bedrock.** Bedrock
requests are SigV4-signed over the exact host, path, and body. Two
consequences are design decisions, not implementation details:

1. Tags ride the INBOUND call only: `/r/{run}/{iter}` path segments and
   `x-agenticledger-*` headers are read and stripped before anything
   else happens; the outbound request is rebuilt clean and re-signed
   with credentials the ledger holds (botocore, standard AWS chain,
   optional `[bedrock]` extra). Signing is the LAST step after final
   body and headers, per the existing ROADMAP note.
2. The ledger never forwards a client signature. A signed inbound
   request is evidence the client thinks it is talking to AWS directly;
   the adapter refuses it with a message naming the fix (point the SDK
   at the ledger with `endpoint_url`, no signing needed client-side, or
   keep client signing and the ledger cannot sit in the middle).

**Gate for Phase A.** Zero behavior change, mechanically enforced: the
corpus (#97) replayed through the old and the new pipelines must
produce byte-identical canonical records, and `scripts/loadtest.py`
numbers must hold within noise. Both run before and after every Phase A
merge.

## 4. The enforcement-state architecture

**Problem.** The kill switch reads `app.state.stopped_runs`, a
per-process set loaded at boot. Loop-guard trips live inside the
tracker. One replica: correct. Two replicas: the wall has holes, which
is a dev-tool tell and a documented caveat we now retire (#100).

**Contract.** Two tiers, honestly separated:

- **Markers (must be replica-coherent):** stopped runs and loop-guard
  trips. Source of truth stays the store (labels rows, as today).
  Each replica keeps a read-through cache with a hard TTL of 2 seconds,
  and invalidates immediately on its own writes. On Postgres, writes
  also `NOTIFY` so peer replicas invalidate in milliseconds; SQLite is
  single-process by nature, where the TTL path is already exact.
  Consequence, stated plainly: with several replicas, a stop takes at
  most two seconds to be enforced everywhere. The dashboard says so on
  the block confirmation when replica mode is detected.
- **Inference state (may be per-replica):** run-signature grouping
  moves into a small store table (tiny rows, low write rate) so that
  inferred-run walls are replica-correct too. Thread stitching and
  repeat streaks stay in process memory: with load-balancer session
  affinity they are exact; without it, flags may fire late on a
  minority of calls, which degrades detection, never enforcement, and
  the deployment guide says exactly that.

**Last cycle, restated.** The #74 family becomes structurally
single-brained: the gate, the capture path, and every replica read the
same markers with a bounded staleness that is written down instead of
discovered.

## 5. UI honesty rules

Written rules a change can be reviewed against, promoted to
ARCHITECTURE.md when this doc lands:

1. Derived state must not freeze: anything computed from "now" (ago
   strings, activity-derived statuses) re-renders on the liveUpdates
   heartbeat even in silence (#82's fix, now a rule).
2. An aggregate that collapses N things states N: no row may show one
   session id while holding five (#86's fix, now a rule).
3. A renamed thing shows its identity: custom names never hide raw ids
   (#76's fix, now a rule).
4. Controls say what they do to the system, not what the user hopes:
   block/allow wording over stop/resume (#81's fix, now a rule).
5. Colors are judgments: green and red only where less or more is
   genuinely better or worse; shape metrics stay neutral (#88's fix,
   now a rule).
6. Mutations update every visible copy of the state in the same render
   (#75's fix, now a rule).

Live Loop (#96) is built against these rules from its first commit,
which is the point of writing them before Phase C.

## 6. Trusted-application work (Phase T, #100)

Riding the phases rather than trailing them:

- **Retention as product:** a `[retention]` config section (days, per
  project overrides), a sweep that runs inside the proxy, audited
  deletes, and a data-handling doc page. Ships with Phase A.
- **Operability:** `/metrics` (Prometheus text format: capture counts,
  refusals, queue depths, store latency), structured log option,
  graceful shutdown draining in-flight captures, and a backup/restore
  guide. Ships with Phase B.
- **Security posture:** SECURITY.md with a disclosure policy and a
  threat-model page: what the proxy sees, where provider keys travel
  (through, never stored), what the AWS credentials for Bedrock can do
  and how to scope them (an IAM policy limited to
  `bedrock:InvokeModel`). Ships with Phase B, because Bedrock is the
  moment the ledger first HOLDS a credential, which changes the story
  and must be documented the same day it becomes true.
- Deferred to 0.11 by name: SSO/OIDC, RBAC beyond the three roles,
  multi-tenancy.

## 8. Decisions (reviewed and approved 2026-08-19)

1. Marker staleness: DECIDED, the 2 second bound. A block click
   finishes instantly and every replica re-reads the markers within 2
   seconds; synchronous fan-out would hang clicks on the slowest or a
   downed replica. The bound is tested and written in the deployment
   guide.
2. Bedrock credentials: DECIDED, standard AWS chain only (env,
   profile, instance role). No credential fields in our config file.
3. Azure naming: DECIDED, its own `azure-openai` tag with its own
   pricing pack; folding into openai would hide the very difference
   being fixed.
4. Live Loop raccoon: DECIDED, no. The whimsy budget stays spent;
   Live Loop earns attention on its own.
